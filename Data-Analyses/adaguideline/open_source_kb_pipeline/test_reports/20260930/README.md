# Source Language and Unicode Compatibility Check

This check follows the English documentation update at commit `0e5072f`. Ten Python source and test files still contained literal Han characters in Unicode test inputs and the frozen legacy review renderer. Those literals now use ASCII Unicode escape sequences. The current repository source can be read without literal Chinese text while retaining the exact runtime strings needed for compatibility with historical review packages and Unicode paths.

For all ten edited Python files, the parsed syntax tree was compared with the version at `0e5072f`, ignoring source-position attributes. Every comparison was identical, and all files compiled successfully. The English review renderer, retrieval behavior, approval fingerprints, and test expectations retain their previous semantics.

## Automated Test Results

The full repository test suite was rerun in the existing macOS Python 3.12.4 environment. Of 364 tests, 312 passed and 52 were skipped because controlled local fixtures were unavailable. There were zero failures and zero errors. The [machine-readable result](public_checkout_tests.json) records the actual time, duration, skipped tests, and SHA-256 hashes of the tested source files.

To run the same test entry point from the pipeline directory, choose a new output file:

```sh
python run_public_tests.py --output outputs/unicode_compatibility_tests.json
```

This was a source compatibility test. It did not rerun the ten-case retrieval experiment, install dependencies into a fresh environment, or perform Windows acceptance testing. The [September 29 retrieval results](../20260929/README.md) remain a separate historical result. Their source hashes describe that earlier publication; the result in this directory records the current escaped source files.

## Repository Content Inspection

At the start of this change, the repository contained 224 tracked paths, including 204 UTF-8 text files. A scan of those filenames and text files found no remaining literal Han characters after the edits. This report and its result file were checked before publication as well.

The binary artifact review covered:

- All 15 tracked PNG images, inspected visually; no Chinese appeared in their titles, axes, legends, labels, or annotations.
- The single tracked PDF, with text extracted from all 25 pages; no Han characters appeared in page text or metadata, and no embedded raster images were present.
- Two valid DOCX files and one XLSX file, with every XML member's text and attributes checked; no Han characters appeared in document prose, tables, worksheet content, comments, or sheet names. No embedded images were present.

Localized font names remain in internal Office font and theme metadata. They are font settings rather than displayed document prose, and the Office files were not rewritten. A tracked 162-byte Word lock file is not a readable DOCX and was excluded from document-content inspection. PDF and Office inspection used extracted text and XML rather than native-application rendering of every page.

The change applies to the current main-branch files. Historical commits and controlled source-bearing knowledge-base packages are retained unchanged. Unicode strings generated by compatibility tests or the legacy renderer still have their original runtime values; escaping their source representation does not translate those historical artifacts.
